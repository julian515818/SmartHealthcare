0一張地圖：ReLU 很好，但還能更好

上一頁看到 ReLU 計算快、梯度不消失、活化稀疏。但它「負值一刀切成 0」的硬開關，也帶來一些問題。後來的改良可以用一句話串起來：

ReLU：x × 0 或 1 的硬開關
Swish／GELU：x × 0～1 平滑調光（門由 x 自己決定）
GLU：(xW) × σ(xV) 可學習的門
SwiGLU：(xV) × Swish(xW) 平滑＋可學習的門

共同主題：「訊號 × 門」。差別只在門是硬的還是平滑的、是固定的還是學出來的。

1ReLU 的缺點一：神經元「死亡」（Dying ReLU）

當某次更新把偏置 b 推得太負，所有輸入的 z = wx + b 都小於 0：輸出全為 0，導數也全為 0，梯度從此傳不進來——這個神經元再也學不動。

2ReLU 的缺點二、三：在 0 有尖角，負值資訊全丟

ReLU導數 ReLU′
  • 尖角（不平滑）：導數在 x = 0 從 0 突然跳到 1。輸入只差一點點，梯度卻可能整個消失或整個出現，最佳化的地形比較崎嶇。
  • 負值資訊全丟：x = −0.1 和 x = −100 的輸出都是 0，網路分不出「有點負」和「非常負」。
  • 輸出非零中心：輸出永遠 ≥ 0，下一層收到的輸入平均值偏正。

共同原因：ReLU 的門是硬開關——不是全開就是全關。

3改良一：Swish／GELU——把硬開關換成「調光器」

ReLU(x) = x · 1[x>0]　　Swishβ(x) = x · σ(βx)　　GELU(x) = x · Φ(x)

σ 為 sigmoid；Φ 為標準常態分布的累積分布函數。三者都是「x × 門」，只是門的形狀不同。β = 1 時的 Swish 也稱為 SiLU。

4改良二：GLU——門不再由 x 自己決定，而是「學出來的」

GLU(x) = (xW + b) ⊗ σ(xV + c)

Dauphin 等人（2017）的門控線性單元（Gated Linear Unit, GLU）用兩個線性投影：一個產生內容 xW，另一個經過 sigmoid 變成門 σ(xV)，再逐元素相乘（⊗）。V 是可訓練參數，所以網路自己學會「哪些特徵、在什麼輸入下該放行」。

示意數值：6 維特徵、3 個輸入詞。「訓練後」的 V 為手工設定，用來呈現學好的門的樣子。

特徵內容 xW門 σ(xV)輸出 ⊗
Swish 和 GLU 的差別：Swish 是 x · σ(x)，門由同一個值自己算出（自我門控）；GLU 的門來自另一組可學習的權重 V，內容與門可以各自學習。

5改良三：SwiGLU——Swish 的平滑 ＋ GLU 的特徵篩選

FFNSwiGLU(x) = ( Swish1(xW) ⊗ xV ) W2

Shazeer（2020）把 GLU 裡的 sigmoid 門換成 Swish：門分支 Swish(xW) 平滑、能保留一點負值；內容分支 xV 保持線性；相乘後再用 W2 投影回原本維度。下面用 dmodel = 3、隱藏寬度 = 4 一步一步算：

6多一個矩陣，參數會變多嗎？——把寬度縮成 2/3

傳統 FFN 有 2 個矩陣（W1、W2），SwiGLU 有 3 個（W、V、W2）。為了公平比較，Shazeer 把隱藏寬度縮成原本的 2/3，參數量就一樣了。

DeepSeek V4 與 Qwen3.8 都是專家混合（MoE）模型：每個專家就是一個 SwiGLU FFN，每個 token 只啟用少數專家——這也正是 Shazeer 2017 年提出的稀疏門控 MoE 想法。

在現代大型語言模型中，SwiGLU 常用來取代 FFN 裡的 ReLU／GELU，幾乎成為新模型的預設選擇。
